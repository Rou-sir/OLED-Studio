# OLED UI 设计器需求与技术审计

- 日期：2026-11-07。
- 审计对象：[需求文档 v0.1](requirements.md)。
- 审计类型：需求完整性、技术可行性、范围边界与验收可执行性；不是现有代码安全审计。
- 现状：工作目录在检查时为空，没有应用代码、构建产物或测试可以审计。
- 方法：核对用户已确认选择、检查需求闭环、参照 U8g2 官方接口/字体格式/转换器源码；未运行技术原型。

## 1. 结论

**需求可作为待审核的开发基线；技术方案有条件成立，尚不满足直接进入完整开发的条件。**

功能覆盖了项目、屏幕参数、多页面、全部八类组件、拖拽属性编辑、图片取模/资源库、ASCII 字体、中文字体转换和双目标 UI 导出。

最重要的两个技术门槛是：

1. 本地 HTML 直接打开时，预览及字体转换运行时能否全部离线加载。
2. 浏览器预览、生成字库以及导出 UI 能否和原生 U8g2 保持逐像素一致。

需要先完成需求审核，再执行阶段 0 的技术验证。本文不把“技术上可能”表述成“已经验证通过”。

## 4. 推荐实现方向，不是已批准的技术选型

### 4.1 前端编辑层

- 可使用现代前端构建工具维护代码，但发布产物必须符合离线直接打开要求。
- Canvas 用于显示 1 bit framebuffer 与编辑辅助层，不独立决定最终字形或几何像素。
- 项目数据层统一管理页面/资源引用；导出、预览和诊断读取相同规范化模型。
- 浏览器数据库作为自动保存；项目包用于显式备份、迁移与恢复。
- 避免先按在线 SPA 设计，最后再尝试补救 `file://` 兼容性。

### 4.2 字库转换

优先验证授权兼容的字体栅格化实现与官方 `bdfconv` 的浏览器构建：

`本地 TTF/OTF + 字符子集 + 像素尺寸 → 字形与度量 → BDF → U8g2 压缩字库 → 原生解码预览`

不建议第一版手写完整 U8g2 字库编码器作为捷径。若不能使用官方转换器或字体栅格化依赖，需解释原因，并用原生对照证明替代方案完整兼容。

转换器运行在浏览器中，不代表一定能从 `file://` 加载。应先验证嵌入字节、内存初始化、Blob Worker 等可行组合，并记录相应浏览器限制；这些只是候选实现，不是已测试的结论。

### 4.3 预览与代码生成

- 预览使用固定版本 U8g2 核心；资源与字形都从真正的 U8g2/XBM 数据解码。
- 图形与资源逻辑优先共享通用 C 核心，Arduino 适配层只负责实例对接。
- 任意多边形辅助函数在两个导出目标中复用，保证相同边界与裁剪。
- 常量存储、AVR 程序存储读取、C++ 实例桥接需要分别验证，不因共享 C 代码就假定自动正确。
- 实际目标 U8g2 版本与预览版本不一致时，导出说明应明确兼容边界。

## 6. 不允许的简化

- 把中文文字转成整段图片后声称已经实现字库管理。
- 用 CSS 字体和字号近似预览后直接输出某个 U8g2 字体。
- 把所有外部取模格式当成 XBM，或靠自动猜测尺寸完成导入。
- 只生成 Arduino C++ 而把 STM32 接入工作全部留给用户改写。
- 要求用户启用本地 HTTP 服务才能用发布版本，却称其为直接打开的离线 HTML。
- 只实现几何控件而把中文转换或图片工具延期，却声称完成第一版。
- 用宽泛异常捕获把解析失败、缺字、保存失败变成成功提示或空白结果。
- 未完成原型、编译或像素对照，就给出“已通过审计，可以完整开发”的结论。

## 8. 证据与限制

- [U8g2 API 参考](https://github.com/olikraus/u8g2/wiki/u8g2reference)：确认文字基线、填充三角形、XBM/XBMP 与页缓冲相关接口。
- [U8g2 字库格式](https://github.com/olikraus/u8g2/wiki/u8g2fontformat)：确认压缩字库、字形偏移/advance 与 Unicode 查找机制。
- [bdfconv 官方源码](https://github.com/olikraus/u8g2/blob/master/tools/font/bdfconv/main.c)：确认 BDF 转换入口、U8g2 输出格式及字符子集参数。
- [U8g2 LICENSE](https://github.com/olikraus/u8g2/blob/master/LICENSE)：确认绘图库和字体具有不同许可条件。

网页与源码检查不能证明某个浏览器打包方案可用。具体版本、第三方转换模块、性能和硬件接入均待后续技术验证。本次没有进行代码开发、依赖安装、构建或硬件测试。

### 实测发现并处理

1. `bdfconv -m "*"` 使用默认字符映射，不等同于提取全部 Unicode；已改为显式字符码点清单，避免中文静默丢失。
2. 官方随附 Windows 转换器与源码构建的压缩结果可不同，但解码后像素相同；验收必须比较像素，不把字节相同作为错误代理。
3. 大于 32,760 字节的字库有 `U8G2_USE_LARGE_FONTS` 条件；解析器识别官方封装，输出提示 32 位目标启用方式和 AVR 子集限制，并避免默认编译静默忽略字库。
4. 开发仓库的 C++ 设备类与部分 C 声明在 Arduino 环境下不同步；Arduino 目标改用同版本官方发布库，没有伪造设备声明或修改驱动。
5. 字体读取是异步操作；增加任务代次检查与立即禁用生成按钮，防止取消后旧任务重新启动或多个任务相互覆盖。

### 尚未完成，不计为通过

- 完整项目格式、资源打包、跨会话保存恢复和浏览器存储异常测试。
- 全量几何边界、旋转和复杂资源输入校验；当前 C 字库导入仅为转换流程使用的受限数据解析器，不宣称完整恶意位流校验已经完成。
- 已建议的 200 组件拖动 p95、10 页项目、内存峰值和正式处理预算；目前没有拖拽编辑器可测。
- Edge 独立兼容验证，以及真实 Arduino / STM32 + OLED 的硬件运行测试。
- 项目/页面管理、组件属性与拖拽、资源管理器、图片取模面板、完整双目标代码生成与最终验收。

核心离线加载、字体转换、原生预览和平台 ABI 风险已有运行证据；保存恢复及其余测试仍须继续落实。后续不得把当前技术验证产物宣称为完成第一版。
